## 第 4 頁｜一句話

**標題**　AIPAR ETA 是實驗室內部的伙食系統

Discord 建檔、揪團、點餐、結算；校內網站只負責查閱。  
金額由程式依庫內價格計算，模型不得自行定價。

- **兩個入口**　Bot 負責操作，網站負責看板。兩邊共用同一份 PostgreSQL。
- **模型的角色**　幫忙讀菜單、聽懂自然語言。錢與帳一律由程式決定。

**講者備註**　這頁是整場的定位句，後面功能都回到這三行。

## 第 5 頁｜功能總覽

**標題**　三件核心能力

1. **菜單建檔與查詢**  
   `/餐廳 新增` 建檔。`/菜單 上傳` 丟照片，或 `/菜單 輸入` 貼文字。辨識結果先當草稿，確認後才上線。
2. **揪團點餐**  
   `/揪團` 在論壇開貼文，自動貼菜單與彙總。按「點餐」選數量與品項，或直接打字。截止後顯示截止時刻，不再倒數。
3. **記帳與分攤**  
   `/結算` 把每人小計寫進帳本。`/帳務 誰欠誰` 給互抵後的欠款與最少轉帳建議。同場同人不會重複計費。

**講者備註**　三塊對應產品範圍。下一頁起各用一張畫面展開。

## 第 6 頁｜菜單建檔與查詢

左欄重點：

- 先登記餐廳，再為它建立菜單版本。
- 照片辨識支援直書菜單；也可以人工貼文字。
- 選用 OCR 對帳，預覽時標出需要人工核對的行。
- 沒有人按下「確認寫入」，菜單不會上線。
- 之後可用指令或 @ bot 問「這家有什麼」。

右圖：校內網站實機截圖，雷荷豆腐鍋專賣店菜單 v1（來源 vision）。

**講者備註**　來源標為 vision，代表圖片辨識後經人工確認上線。

---

## 第 7 頁｜揪團點餐

左欄重點：

- 管理員先指定論壇頻道，開團可 ping 身分組。
- Bot 開論壇貼文，貼上菜單與持續更新的彙總。
- 點餐面板可選 1–10 份，品項可複選。
- 也可以打「我要一個豆腐鍋跟一份地瓜薯條」。
- 要改就說「取消地瓜薯條」，或按「清除我的」。
- 價格永遠取自已上線的菜單，不接受口頭報價。

右圖：Discord 介面示意（字串、按鈕與標誌取自本專案）。

**講者備註**　示範「按鈕」與「自然語言」兩條路並存。Ack Reaction（👀）出現在等待整理點餐時。

## 第 8 頁｜記帳與分攤

結算時寫下每人應付，並記住這場要把錢拿給誰。  
餘額由帳本紀錄加總得出，不另存一個會飄的數字。

| 指令 | 作用 |
| --- | --- |
| `/結算` | 每人小計寫成帳本紀錄。同場同一個人只計一次。 |
| `/帳務 我的` | 看自己的結餘，以及要拿給誰、誰要還你。 |
| `/帳務 誰欠誰` | 全體互抵後的欠款，加上最少轉帳建議。 |
| `/帳務 付款` | 記下實際付款；指定「付給」誰才抵銷債務。 |

**講者備註**　結餘與債務是兩件事：結餘是吃了多少、付了多少；債務是該把錢拿給哪一位。

## 第 9 頁｜使用路徑

**標題**　一場午餐，六個步驟

1. `/設定 論壇`　指定揪團頻道，需要時再設通知身分組
2. `/餐廳 新增`　寫下店名、別名、電話
3. `/菜單 上傳`　草稿 →「確認寫入」才上線
4. `/揪團`　選餐廳與截止分鐘數，Bot 開論壇貼文
5. 按「點餐」或打字；要改就說「取消…」
6. `/結算`　每人小計入帳，並記下收款人

網站對應：`/` 儀表板、`/restaurants` 菜單、`/sessions` 該場彙總、`/ledger` 誰欠誰。

**講者備註**　跟著 1 到 6 走一遍。強調第 3 步的人工確認與第 6 步的結算。

## 第 11 頁｜技術棧

**標題**　實驗室機器跑得動的組合

| 層 | 選用 |
| --- | --- |
| 執行期 | Node.js 24，TypeScript 直接執行，沒有前端建置步驟 |
| 資料 | PostgreSQL 18.6；金額以整數計算，顯示為新台幣元 |
| 編排 | Docker Compose：postgres、web、bot 三個容器 |
| Discord | discord.js 14；斜線指令、Embed、按鈕與下拉 |

| 辨識 | 視覺模型讀菜單圖；可選 PP-OCRv6 做版面對帳 |
| 時區 | 全程台北時間，日期 YYYY-MM-DD、時間 HH:MM:SS |

**講者備註**　講「為什麼這樣選」：校內機器、免費 API、無公有網域。

## 第 12 頁｜架構

**標題**　兩個入口，一份資料

實驗室成員 → Discord bot；校內瀏覽器 → 網站。  
兩者都進 PostgreSQL。只有 bot 會呼叫免費 LLM 閘道。  
分層：`shared` → `db` → `domain` → `llm` → `bot`／`web`。領域邏輯不認識 Discord 或 HTTP。

**講者備註**　指出「錢在資料庫、模型只做對應」。

---

## 第 13 頁｜設計原則

**標題**　讓帳算得準、讓人看得懂

1. **價格只來自菜單**　模型負責指到哪一項、要幾份。應付金額由程式查菜單計算。
2. **草稿必須有人確認**　圖片辨識與文字解析都先產生草稿，「確認寫入」才上線。
3. **規則優先、模型墊底**　對得到的品名就不打模型；沒有金鑰時，按鈕與下拉仍可點餐。
4. **兩種語言一起提供**　Discord 語言為中文時用繁體中文，其餘用英式英文。

**講者備註**　若有人問「AI 會不會算錯錢」，答案是錢不經過模型。
